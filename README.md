# Family Secure Messenger

Минималистичный self-hosted мессенджер для семьи с настоящим E2EE, авторизацией только через сид-фразу и автоматическим удалением сообщений через 48 часов.

## Цели проекта

- Текстовые сообщения (пока без файлов, голосовых и звонков)
- End-to-End Encryption: сервер никогда не видит plaintext
- Авторизация **только** через сид-фразу (BIP39)
- Сообщения живут максимум 48 часов (TTL в Redis)
- Работает на самом дешёвом VPS: 1 GB RAM / 1 CPU / 15 GB SSD
- Простой веб-клиент (PWA)
- Код должен быть понятным и пригодным для доработки с помощью нейросетей

## Архитектура

### Высокоуровневая схема

```
[Клиент 1] ←→ WebSocket ←→ [FastAPI + Redis] ←→ WebSocket ←→ [Клиент 2]
     ↑                                              ↑
  WebCrypto                                   WebCrypto
 (шифрование)                               (шифрование)
```

Сервер — **слепой ретранслятор**. Он хранит и передаёт только ciphertext.

### Компоненты

| Компонент              | Технология                          | Назначение                                      |
|------------------------|-------------------------------------|-------------------------------------------------|
| Backend                | Python 3.11+ / FastAPI + Uvicorn    | API + WebSocket                                 |
| Хранилище сообщений    | Redis (с TTL)                       | Временное хранение ciphertext                   |
| Криптография (сервер)  | PyNaCl + cryptography               | Проверка подписей                               |
| Криптография (клиент)  | Web Crypto API + libsodium.js       | Генерация ключей, шифрование, подписи           |
| Сид-фраза              | BIP39 (12 слов)                     | Единственный способ входа                       |
| Фронтенд               | Vanilla JS / Svelte / React (на выбор) | Простой и лёгкий клиент                      |

### Модель идентичности

1. Пользователь вводит / генерирует 12-словную сид-фразу (BIP39).
2. Из сид-фразы через PBKDF2 / Argon2id + HKDF выводятся:
   - `identity_private_key` (Ed25519)
   - `identity_public_key` (Ed25519)
   - `encryption_private_key` (X25519)
   - `encryption_public_key` (X25519)
3. `identity_public_key` (в hex или base64) становится **постоянным идентификатором** пользователя.
4. Сервер знает только публичные ключи и никогда не видит сид-фразу и приватные ключи.

### Протокол сообщений (упрощённый, но безопасный)

Для первой версии используем простой, но корректный подход:

- Для каждого диалога (1:1) клиенты обмениваются `encryption_public_key`.
- Сообщения шифруются с помощью **X25519 ECDH + XChaCha20-Poly1305** (или AES-256-GCM).
- Каждое сообщение содержит:
  - `from` — identity_public_key отправителя
  - `to` — identity_public_key получателя
  - `ciphertext`
  - `nonce`
  - `timestamp`
  - `signature` (Ed25519 подпись всего содержимого)

Позже можно добавить Double Ratchet, но для семьи первой версии достаточно.

### Хранение

- Все сообщения кладутся в Redis с ключом вида `msg:{to_pubkey}:{message_id}`
- TTL = 172800 секунд (48 часов)
- После успешной доставки клиенту сообщение можно сразу удалять (опционально)
- На сервере **нет** долговременного хранилища истории

## Безопасность (важные принципы)

- Приватные ключи **никогда** не покидают устройство пользователя.
- Сервер не может расшифровать сообщения даже при полном компрометировании.
- Сид-фраза — единственный способ восстановления аккаунта. Потерял сид → аккаунт потерян навсегда.
- Рекомендуется хранить сид-фразу в менеджере паролей или на бумаге.
- Все соединения только через HTTPS / WSS.
- Rate limiting на отправку сообщений.
- Максимальный размер сообщения ограничен (например, 4–8 КБ).

2. Добавление контакта по публичному ключу / QR
3. Отправка и получение зашифрованных текстовых сообщений
4. Автоматическое удаление через 48 часов
5. Простой и понятный веб-интерфейс
6. Работа в виде PWA (можно добавить на домашний экран)
